## Context
Running `bun run pipeline ingest` with large date ranges can unexpectedly consume thousands of GitHub API calls, potentially hitting rate limits:
- **Authenticated users**: 5,000 requests/hour
- **GitHub Apps**: 15,000 requests/hour

This is especially problematic for:
- Historical data ingestion (e.g., `--after 2024-01-01` on 20+ repos)
- First-time project setup
- Large active repositories with thousands of PRs/issues

### Real-world example:
- **23 repositories** × **52 weeks** × **~6 API calls per week** = **~7,176 API calls**
- **Outcome**: Rate limit exhaustion, 1-2 hour wait, failed ingestion

Users need visibility into API cost before committing to large ingestions.

## Proposal
Add `--estimate-only` flag and automatic pre-flight cost estimation that shows:
- Estimated API call count
- Risk level (LOW/MEDIUM/HIGH)
- Estimated duration
- Warning for HIGH risk operations

## Implementation

### Add cost estimation function to `cli/analyze-pipeline.ts`:

```typescript
// Simple API cost estimation helper
function estimateApiCalls(
  repositories: { owner: string; name: string }[],
  intervalCount: number,
): { total: number; risk: string; duration: number } {
  const baseCallsPerRepo = intervalCount * 6; // ~6 calls per interval (PRs, issues, commits)
  const total = repositories.length * baseCallsPerRepo;

  const risk = total > 2000 ? "HIGH" : total > 500 ? "MEDIUM" : "LOW";
  const duration = Math.ceil(total / 60); // ~60 calls per minute with rate limiting

  return { total, risk, duration };
}
```

### Add CLI flag to ingest command:

```typescript
program
  .command("ingest")
  // ... existing options
  .option(
    "--estimate-only",
    "Show API cost estimation without executing ingestion",
    false,
  )
```

### Add estimation logic before execution:


17:T1264,# Enhancement: Add graceful shutdown to CLI pipeline

## Context
Long-running ingestion pipelines (historical data ingestion spanning months) can take hours, especially for large active repositories. Currently, pressing Ctrl+C immediately terminates the process, losing all in-progress work.

This is common when:
- Ingesting historical data for the first time
- Running large date range imports (e.g., `--after 2024-01-01`)
- Processing multiple large repositories
- Debugging or testing ingestion locally

## Proposal
Add graceful shutdown handling that:
1. **First Ctrl+C**: Completes current operation, saves progress, then exits cleanly
2. **Second Ctrl+C**: Force exits immediately if user needs to stop now
3. Shows clear messaging about shutdown state
4. Allows resuming with same command (pipeline skips already-processed data)

## Implementation

### Add to `cli/analyze-pipeline.ts` (before program definition):

```typescript
// Graceful shutdown handler
let gracefulShutdown = false;
process.on("SIGINT", () => {
  if (!gracefulShutdown) {
    gracefulShutdown = true;
    (global.process as { gracefulShutdown?: boolean }).gracefulShutdown = true;
    console.log(
      "\n⚠️  Graceful shutdown initiated... Current operations will complete.",
    );
    console.log("Press Ctrl+C again to force exit.");
  } else {
    console.log("\n🔴 Force exit requested.");
    process.exit(1);
  }
});
```

### Update ingest command execution (in ingest action handler):

```typescript
try {
  await ingestPipeline(undefined, context);

  if (gracefulShutdown) {
    rootLogger.warn(
      "⚠️  Ingestion interrupted but current operations completed successfully!",
    );
    rootLogger.info(
      "💡 You can resume by running the same command again - the pipeline will skip already processed data.",
    );
  } else {
    rootLogger.info("✅ Ingestion completed successfully!");
  }
} catch (error: unknown) {
  if (String(error).includes("GRACEFUL_SHUTDOWN")) {
    rootLogger.warn(
      "⚠️  Ingestion gracefully interrupted. Progress has been saved.",
    );
    rootLogger.info("💡 Resume by running the same command again.");
    return;
  }
  throw error;
}
```

### Update `src/lib/pipelines/types.ts` mapStep to respect shutdown:

```typescript
const results = await pMap(
  inputs,
  async (item, index) => {
    // Check for graceful shutdown before processing each item
    if (
      global.process &&
      (global.process as { gracefulShutdown?: boolean }).gracefulShutdown
    ) {
      context.logger?.warn(
        `Graceful shutdown requested. Skipping remaining items after ${index}/${inputs.length}`,
      );
      throw new Error("GRACEFUL_SHUTDOWN");
    }
    return await operation(item, context);
  },
  {
    concurrency: Math.max(1, concurrency),
    stopOnError: false, // Continue processing other items even if one fails
  },
);

return results.filter((r) => r !== null); // Filter out any null results from interrupted operations
```

## Root Cause

## Solution
Replace hardcoded path with dynamic loop over all repository directories:

```yaml
- name: Copy yesterday's stats for all tracked repositories
  run: |
    YESTERDAY=$(date -d "yesterday" +'%Y-%m-%d')
    echo "Processing stats for date: ${YESTERDAY}"

    # Find all repository directories and copy stats files
    # Pattern matches owner_repo format, excluding dump/ and summaries/
    for repo_dir in data/*/; do
      repo_name=$(basename "$repo_dir")

      # Skip non-repository directories
      if [[ "$repo_name" == "dump" || "$repo_name" == "summaries" ]]; then
        continue
      fi

      stats_file="${repo_dir}stats/day/stats_${YESTERDAY}.json"
      target_file="${repo_dir}stats/day/stats.json"

      if [ -f "$stats_file" ]; then
        cp "$stats_file" "$target_file"
        echo "Copied stats for ${repo_name}"
      else
        echo "Warning: No stats file found for ${repo_name} on ${YESTERDAY}"
      fi
    done

    echo "Stats copy complete"
```
