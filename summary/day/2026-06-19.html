Development on June 19 focused on stabilizing the Eliza Cloud infrastructure following a production incident, decommissioning legacy routing, and enhancing the dedicated agent experience. The team successfully resolved critical database connection exhaustion and billing leaks while improving mobile build reliability and agent orchestration performance.

✅ Completed Work

Cloud Infrastructure & Routing

  • Decommissioned BitRouter in favor of a Cloudflare Worker-based gateway to simplify LLM routing and improve reliability (elizaos/eliza#8741, elizaos/eliza#8738).
  • Resolved production connection exhaustion and database scaling issues by implementing env-tunable pools and Cloudflare KV caching (elizaos/eliza#8696, elizaos/eliza#8665).
  • Mitigated rate-limiting by adding round-robin load balancing for Cerebras API keys (elizaos/eliza#8735).
  • Resolved critical billing leaks, including container stop logic and deprovisioning issues (elizaos/eliza#8342).

Agent Orchestration & Performance

  • Improved agent performance by replacing TensorFlow.js with a native ggml YOLOv8n detector and adding a "LEAN_CHAT_PLUGINS" preset to reduce cold-boot times (elizaos/eliza#8725, elizaos/eliza#8730).
  • Introduced parity features for Codex/Claude-Code, including MCP auto-inheritance and sub-agent nesting (elizaos/eliza#8740).

Mobile & UI Experience

  • Fixed Android build regressions ensuring web assets are correctly bundled into APKs (elizaos/eliza#8387).
  • Streamlined user experience with a new sign-in agent picker and auto-skipping of runtime pickers on cloud-only hosts (elizaos/eliza#8721, elizaos/eliza#8742).
