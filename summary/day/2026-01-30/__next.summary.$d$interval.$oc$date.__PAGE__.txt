## Key Changes

### Streamable HTTP Transport Support
- Use `StreamableHTTPClientTransport` from `@modelcontextprotocol/sdk` for `"http"` and `"streamable-http"` types
- Keep `SSEClientTransport` only for legacy `"sse"` type
- Aligns runtime behavior with the documented config and `HttpMcpServerConfig` type definition

**Before:**

```typescript
// Always returns SSE regardless of config type
return new SSEClientTransport(new URL(config.url));
```

**After:**

```typescript
if (config.type === 'sse') {
  return new SSEClientTransport(new URL(config.url), { requestInit });
}
return new StreamableHTTPClientTransport(new URL(config.url), { requestInit });
```

### Custom Headers Support
- Added `headers?: Record<string, string>` to `HttpMcpServerConfig`
- Passed through to both transports via `requestInit`
- Enables `Authorization`, API key headers, and other custom headers without workarounds

```json
{
  "my-server": {
    "type": "http",
    "url": "https://example.com/mcp",
    "headers": {
      "Authorization": "Bearer my-api-key"
    }
  }
}
```

### Type Updates
- Added `StreamableHTTPClientTransport` to `McpConnection.transport` union type
- Updated local type annotations in `initializeConnection`

## Impact
- **Correctness**: `type: "http"` now actually uses Streamable HTTP instead of SSE
- **No breaking changes**: `type: "sse"` behavior is unchanged
- **Headers**: Allow authenticated MCP server connections using headers

`buildHttpClientTransport` currently returns `SSEClientTransport` for all HTTP transport types (`"http"`, `"streamable-http"`, `"sse"`), despite the README and type definitions advertising Streamable HTTP support. This PR implements the actual transport routing and adds custom headers passthrough.

## Key Changes

### Streamable HTTP Transport Support
- Use `StreamableHTTPClientTransport` from `@modelcontextprotocol/sdk` for `"http"` and `"streamable-http"` types
- Keep `SSEClientTransport` only for legacy `"sse"` type
- Aligns runtime behavior with the documented config and `HttpMcpServerConfig` type definition

**Before:**

```typescript
// Always returns SSE regardless of config type
return new SSEClientTransport(new URL(config.url));
```

**After:**

```typescript
if (config.type === 'sse') {
  return new SSEClientTransport(new URL(config.url), { requestInit });
}
return new StreamableHTTPClientTransport(new URL(config.url), { requestInit });
```

### Custom Headers Support
- Added `headers?: Record<string, string>` to `HttpMcpServerConfig`
- Passed through to both transports via `requestInit`
- Enables `Authorization`, API key headers, and other custom headers without workarounds

```json
{
  "my-server": {
    "type": "http",
    "url": "https://example.com/mcp",
    "headers": {
      "Authorization": "Bearer my-api-key"
    }
  }
}
```

### Type Updates
- Added `StreamableHTTPClientTransport` to `McpConnection.transport` union type
- Updated local type annotations in `initializeConnection`

## Impact
- **Correctness**: `type: "http"` now actually uses Streamable HTTP instead of SSE
- **No breaking changes**: `type: "sse"` behavior is unchanged
- **Headers**: Allow authenticated MCP server connections using headers
