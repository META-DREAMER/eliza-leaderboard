14:T92c,**Describe the bug**  
The `msg_id` and `agent_id` are used to create a UUID for messages, leading to potential collisions:  

https://github.com/elizaOS/eliza/blob/227baf7bd62394a50ae261e934669e4a9520b87f/packages/client-telegram/src/messageManager.ts#L1266C2-L1268C23

```typescript
const messageId = stringToUuid(message.message_id.toString() + "-" + this.runtime.agentId) as UUID;
```

If the same `msg_id` is used in a different channel, the agent incorrectly assumes the memory already exists and skips creating a new memory:  

https://github.com/elizaOS/eliza/blob/227baf7bd62394a50ae261e934669e4a9520b87f/packages/core/src/memory.ts#L172C1-L190C6

```typescript
async createMemory(memory: Memory, unique = false): Promise<void> {
    // TODO: check memory.agentId == this.runtime.agentId

    const existingMessage =
        await this.runtime.databaseAdapter.getMemoryById(memory.id);

    if (existingMessage) {
        elizaLogger.debug("Memory already exists, skipping");
        return;
    }
}
```

**To Reproduce**  
1. Use the same `msg_id` in a different chat or channel (e.g., in Telegram).  
2. Attempt to create a memory for the new message.  
3. Observe that the memory creation is skipped due to the `msg_id` collision.  

**Expected behavior**  
Memory creation should account for different channels or rooms. The system should generate a unique `UUID` by including the `room_id` in the `msg_id` creation process to avoid collisions.  

**Screenshots**  

We encountered an issue in Telegram where the message already existed for a different user.

### A log before memory creation:

<img width="1091" alt="Image" src="https://github.com/user-attachments/assets/c659c325-55aa-424e-aa68-2423754229b0" />

### It's clearly visible that even with the same message ID, the room and user are different:

<img width="860" alt="Image" src="https://github.com/user-attachments/assets/4d2a1e1f-a56a-4bbd-851c-e9fcd08d5fbc" />

**Suggested solution**    
A potential solution would be updating the UUID creation logic to replace `agent_id ` with `room_id` in addition to `msg_id` becuase `room_id` is generated based on `agent_id` already. However, further research is needed to confirm whether collisions involving `room_id` are possible.
