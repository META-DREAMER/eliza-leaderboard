### What changed
- In `packages/service-interfaces/package.json`:
  - Added `publishConfig` so a new scoped package publishes publicly to npm.
- In `.github/workflows/release.yaml`:
  - Added a fallback step after the main `lerna publish from-package`:
    - Enumerates monorepo packages via `lerna ls --json`.
    - For each, checks `npm view <name>@<version>`.
    - Publishes any not yet on npm using `npm publish --access public --tag <dist-tag>`.
  - Keeps existing versioning flow via Lerna; no change to tagging or git steps.

### Why
- CI failed when publishing the newly added `@elizaos/service-interfaces`:
  - New scoped package lacked `publishConfig.access=public`.
  - Bulk publish can leave new packages unpublished; the fallback ensures first-time publishes succeed automatically.

### How it works
- Primary path: `lerna publish from-package --dist-tag <alpha|beta|latest>`.
- Fallback (only on failure): publish only the missing packages with the same dist-tag, preserving version alignment with the rest of the release.

### Impact
- New packages (like `@elizaos/service-interfaces`) will publish on first release without manual intervention.
- Existing packages are unaffected; versions remain synchronized via `lerna version`.

### Security
- Continues using `secrets.NPM_TOKEN` for auth.
- No changes to permission scopes.
