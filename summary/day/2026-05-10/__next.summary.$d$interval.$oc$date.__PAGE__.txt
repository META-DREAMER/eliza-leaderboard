# Background

## What does this PR do?

Adds a first-party `@elizaos/plugin-zai` package under `plugins/plugin-zai`.

The plugin uses z.ai’s Anthropic-compatible API endpoint:

```txt
https://api.z.ai/api/anthropic/v1

It supports:

	•	TEXT_SMALL
	•	TEXT_LARGE
	•	canonical env var: ZAI_API_KEY
	•	legacy env var fallback: Z_AI_API_KEY
	•	configurable small/large model ids
	•	configurable base URL
	•	optional telemetry and CoT budget settings

This also updates elizaOS provider wiring so z.ai onboarding/default provider config points to:

@elizaos/plugin-zai

instead of:

@homunculuslabs/plugin-zai

What kind of change is this?

Features — non-breaking change which adds functionality.

Why are we doing this? Any context or related work?

Milady already exposes z.ai in onboarding/provider setup, but the provider plugin is not available as a first-party elizaOS plugin. That causes the z.ai setup flow to fail or become unavailable in settings.

This PR makes z.ai an upstream elizaOS plugin so Milady can consume it normally after approval/release, without downstream package-mode workarounds.

Documentation changes needed?

My changes require a change to the project documentation.

I have updated the documentation accordingly.
