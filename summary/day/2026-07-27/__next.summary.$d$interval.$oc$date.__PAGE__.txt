## Outcome

This makes chat streaming a single, observable provider → runtime → SSE → React → database pipeline and removes latency policy from correctness CI.

The runtime now has one owner for assistant-message persistence, the SSE completion frame carries the exact committed IDs, the client reconciles optimistic messages in place, and normal streaming performs no post-response history reload. Failed persistence emits an error and never a fake `done`.

## Runtime and persistence

- Return the exact response-memory IDs committed by `DefaultMessageService`.
- Reuse those IDs in the chat route instead of writing or reading the assistant response a second time.
- Preserve callback-before-persistence delivery for fast first response, with the same-room persistence barrier added upstream, while withholding SSE `done` until the write succeeds.
- Mark genuinely ephemeral responses explicitly; never invent a database ID.
- Treat delta streams as deltas. The previous overlap heuristic could corrupt `Fast streaming stays smooth.` into `Fastreaming staysmooth.`.
- Remove the hidden 30-second runtime-ready gate.
- Remove the implicit 180-second chat-generation abort, 60-second browser SSE idle abort, 60-second trajectory-finalization abort, and 5-second conversation-restore race. Cancellation is now caller-owned through `AbortSignal` unless a caller explicitly configures a boundary.
- Move trajectory persistence/finalization off the visible-response path while tracking it as post-delivery work.

## Providers, cache, and database

- Providers selected for a compose run execute concurrently through one `Promise.all`.
- Stage 1 excludes context it cannot consume; the planner reuses all already-composed provider results and refreshes only `RECENT_MESSAGES` when an early reply changed history.
- Replace mutable one-second identity/entity caches with exact turn-scoped promise memoization, rejection eviction, and explicit invalidation.
- Memoize sender-role, room, and related-entity reads within a turn.
- Skip attachment-history database work for ordinary text turns.
- Make SQL memory creation one atomic `INSERT ... ON CONFLICT DO NOTHING RETURNING`, removing the read-before-write race and extra database round trip.
- Cache only successful shared-agent scope authorization. Failed 401/403/404 hydration is never persisted, so a corrected credential, tier, or agent row is observed on the next authoritative attempt instead of serving a stale denial for 30 seconds.

## Browser behavior

- Reconcile optimistic user/assistant IDs in place from the completion frame.
- Do not reload conversation history after an ordinary successful response.
- Reload only when the response is action/incomplete or committed IDs are unavailable.
- Replace requestAnimationFrame token throttling—which can stop making progress in background tabs—with microtask burst coalescing and a synchronous terminal flush.
- Remove the reconnect debounce/speculative resend path; user-triggered resend starts immediately and remains explicit.
- Add the missing `rate_limited` SSE contract.

## CI and telemetry

- Replace the ~1,000-line latency workflow with a small, manual, observational workflow.
- Remove numeric latency acceptance thresholds, regression ratchets, production-code-changed/test-changed gates, and the workflow self-test enforcing those policies.
- Run direct and gateway observations concurrently and upload raw JSONL. Telemetry reports numbers; it does not decide correctness.
- Remove numeric enforcement from inference-auth latency tooling.
- Add a real browser telemetry harness using the production route, production stream client, `useChatSend`, React transcript, real HTTP/SSE, and PGLite.
- Expand the Cerebras runner to cover the complete production chat flow plus an explicit concurrent sweep of every registered provider.
