15:T92e,## Problem

`loadDefaultMasterKeySync` resolves a single persistent process-wide master key, but it is invoked **once per credential file** decoded by `account-storage.ts` (`masterKey()` → `decodeAccountRecord`). A `listAccounts()` over N pooled accounts therefore re-resolves the same key N times:

- **Keychain hosts:** N `readKeychainKeySync` child-process spawns, each ~80-150ms (cold Node boot + `@napi-rs/keyring` dynamic load + Secret Service round trip).
- **Passphrase hosts:** N scrypt derivations at 2^15 cost, ~90ms each.

With ~17 pooled subscription accounts this is **~2.5s of serialized, redundant key resolution**, and it runs inside the account-pool **lease** that every chat turn takes before its first model call.

### Observed impact

On a live deployment the `model:TEXT_EMBEDDING` inference span measured **1.4–9.6s** while the embedding backend itself (`curl` to the same local endpoint) answered in **20-40ms**. `strace` of a turn showed the lease blocking on ~17 keychain child processes (fd read of the base64 key) back-to-back before the embedding HTTP call was even issued — the span wraps the lease, so the redundant key work is charged to the embedding.

## Fix

Memoize the resolved key per `service/account` for the process lifetime.

- The value already lives in process memory for the duration of every vault/credential op; the cache is keyed by the same `service/account` tuple the resolver reads.
- **Security posture unchanged:** no key is ever fabricated, failures are never cached (transient keychain/passphrase errors still retry on the next call), and the `ELIZA_VAULT_PASSPHRASE` length guard still runs before the cache lookup.
- Adds a test-only `resetLoadDefaultMasterKeySyncCache()`.

## Test

`packages/auth/test/master-key-sync-cache.test.ts` asserts reference identity across a 17-call fan-out (simulating a `listAccounts()` decode loop):

- **Fails on clean develop:** un-memoized resolver returns a fresh `Buffer` per call → `expect(key).toBe(first)` fails.
- **Passes with the memo:** one resolution serves the whole fan-out.

The test tolerates the absence of the reset helper (falls back to a no-op) so the *behavioral* identity assertion is the bidirectional signal, not the new API symbol.

Existing `keychain-process.test.ts` (7 tests) still passes.
