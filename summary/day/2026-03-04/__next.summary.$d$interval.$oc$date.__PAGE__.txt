## What it does

- **5 actions:** check balances, transfer tokens, swap (Uniswap V3 + Jupiter), bridge cross-chain (CCTP V2, 17 chains), pay x402 endpoints
- **Wallet provider** that injects balance context into the agent conversation
- **Non-custodial** — agent holds its own private key. No Privy, no Coinbase CDP, no vendor lock-in
- **EVM + Solana** — Base, Arbitrum, Optimism, Ethereum + Solana mainnet/devnet

## Install

```bash
npm install elizaos-plugin-agentwallet agentwallet-sdk
```

## Quick start

```typescript
import { agentWalletPlugin } from "elizaos-plugin-agentwallet";

// Add to your ElizaOS agent
const agent = createAgent({
  plugins: [agentWalletPlugin],
  settings: {
    AGENTWALLET_PRIVATE_KEY: "0x...",
    AGENTWALLET_CHAIN: "base",
  },
});

// Agent can now: check balances, transfer, swap, bridge, pay x402 endpoints
```

## Why non-custodial matters

The current plugin-evm uses LiFi for bridging but has no spend limits, no x402 micropayments, and no Solana Jupiter swaps. This plugin wraps `agentwallet-sdk` (v3.0.0, 629 tests, MIT) which gives agents a complete financial stack without any custodial risk.

Two bootstrap providers inject identical action result data into the LLM context, wasting tokens:

RECENT_MESSAGES (position 100, recentMessages.ts) — generates # Recent Action Executions
ACTION_STATE (position 150, actionState.ts) — generates # Recent Action History
Both fetch action_result messages from DB, group by runId, and format identically. The result: the same action runs appear twice under different headings in every LLM prompt.

Additionally, ACTION_STATE has no limit on the number of runs or text length, causing large thought and reply texts (500-2000 chars each) to bloat the context.

Estimated Token Waste
From a real production context: 3 runs × (~400 char thought + ~500 char reply) × 2 (duplication) = ~5400 chars (~1350 tokens) wasted per prompt.

Solution
Three changes in packages/plugin-bootstrap/src/:

1. recentMessages.ts — Remove action results generation
Set actionResultsText = ''. ACTION_STATE already covers this with richer data (action plan, working memory, recent action memories).

2. actionState.ts — Add .slice(-3) limit on action runs
Only include the 3 most recent runs. LLM doesn't need full history.

3. actionState.ts — Add character limits on thought + reply text
planThought: max 200 chars (~50 tokens)
text (generated reply): max 300 chars (~75 tokens)
After fix
