The current initialization flow has several inefficiencies:
1. Sequential check-then-insert patterns with race condition potential
2. Multiple round-trips to DB for existence checks before inserts
3. Sequential operations that could run in parallel

## Solution

### 1. Atomic Upserts (plugin-sql/base.ts)

Replace check-then-insert with `INSERT ... ON CONFLICT DO NOTHING`:

```typescript
// Before: Two queries + race condition
const existing = await this.getWorld(world.id);
if (existing) throw new Error('World already exists');
await this.db.insert(worldTable).values(world);

// After: Single atomic query
await this.db.insert(worldTable).values(world).onConflictDoNothing();
```

Applied to:
- `createWorld()` - returns silently if world exists
- `createEntities()` - skips existing entities in batch

### 2. Parallel Initialization (core/runtime.ts)

```typescript
// Before: Sequential
await this.ensureWorldExists();
await this.runMigrations();
const entity = await this.getEntityById(entityId);
const room = await this.getRoomById(roomId);

// After: Parallel where possible
await Promise.all([
  this.ensureWorldExists(),
  options?.skipMigrations ? Promise.resolve() : this.runMigrations()

const [entity, room] = await Promise.all([
  this.getEntityById(entityId),
  this.getRoomById(roomId)
]);
```

- `ensureWorldExists()` - Always calls `createWorld()`, DB handles duplicates
- `ensureRoomExists()` - Always calls `createRoom()`, DB handles duplicates
- `ensureEntity()` - New method using upsert pattern

17:T7eb,There are three different states of interacting with public agents. They have fundamentally different user intents and should have a distinct UI.

## State 1: Unauthenticated Visitor (Not Signed In)

**User Intent:** "I clicked a link on Twitter, I'm curious, let me try this agent"

**What they should see:**

* Clean chat interface focused on the agent
* Agent avatar, name, @username, and brief bio/description
* **No** Private/Public toggle
* **No** Edit button
* **No** Fork button (yet—they need to sign up first)
* Copy shareable link button to share with others

**Interaction model:**

* Allow **2-3 free messages** before soft gate
* After limit: "Sign up to continue chatting" overlay

## State 2: Authenticated Non-Owner (Signed In, Not Creator of Agent)

**User Intent:** "I want to chat with this agent OR I want to make my own version"

**What they should see:**

* Chat interface
* Agent info + creator attribution
* **"Chat"** and **"Fork"** buttons (NOT Edit)
* **No** Private/Public toggle
* Clear indication this isn't their agent
* Copy shareable link button to share with others

## State 3: Owner (Signed In, Is Creator)

**User Intent:** "I want to manage/edit my agent"

**What they should see:**

* Full control UI
* **Chat** and **Edit** tabs
* **Private/Public toggle** with clear state indicator
* Share button (when public)
* Analytics/stats (future: views, chats, forks)<br><br>
