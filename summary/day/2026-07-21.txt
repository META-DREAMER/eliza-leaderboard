- server-side cryptographic random generation,
- short shared TTL, recommended 10 minutes,

## Design

Add a durable turn record keyed by the Discord message id with an explicit
lifecycle:

```
RECEIVED ──▶ DISPATCHED ──▶ REPLIED   (terminal)
                    └──────▶ FAILED    (terminal, retries exhausted)
```

On redelivery / process restart, instead of blindly returning when the inbound
memory exists:

- **terminal (REPLIED / FAILED)** → genuine no-op
- **non-terminal + a reply memory already exists** → reconcile to REPLIED, **no
  resend**
- **non-terminal, no reply, retry budget remains** → **resume** the reply path
- **retry budget exhausted** → explicit terminal **FAILED** (no silent drop)

### Delivery model: send-then-record + reconcile probe (documented choice)

The connector already writes a durable **outbound reply memory** for every
message it emits (`content.inReplyTo = <inbound id>`,
`metadata.platformMessageId = <discord reply id>`). That reply memory **is** the
authoritative record-of-send. Rather than add a second "reserved-before-send"
outbox row that can itself desync from Discord on a crash, we **reconcile
against the reply memory the send path already produces**: before re-dispatching
a resumed turn we probe for an existing reply to this inbound; if one exists the
reply already went out (crash in the send↔record gap) and we reconcile to
REPLIED without resending. Bounded retries are safe because the send path is
content-idempotent via #15601's outbound reservation and #13054's outbound
memory dedupe.

The **#16696 pre-persistence retry semantics are preserved**: a failure before
the durable claim leaves nothing persisted and stays retryable.

28:T106e,## What

Bounded retention for the append-only core memory partitions (`memories` + the `embeddings` that cascade with them). These grow one row per turn/fact/fragment/document forever with no upstream pruning — the failure class behind an unbounded-PGlite disk-fill. Nothing in the runtime bounds them today.

## Growth surfaces (audit)

| table | growth | prior bound | this PR |
|---|---|---|---|
| `memories` | 1 row / turn·fact·fragment·doc | none | **age + count prune** |
| `embeddings` | 1:1 w/ memories, up to ~12KB/row (3072-dim) | cascade-on-memory-delete only | pruned via cascade in `deleteManyMemories` |
| `logs` | 1 row / structured log | cascade on entity/room delete only | out of scope (flagged for follow-up — biggest table empirically) |
| `central_messages` | 1 row / message | cascade on channel delete only | out of scope (flagged) |
| `memory_access_logs` | append-only | none | out of scope (flagged) |

`memories`/`embeddings` is the dominant always-growing surface (every turn), so it is addressed first. Empirically on a scratch DB after a smoke run, `logs` was actually the largest table (736 rows / 2.4 MB vs memories 188 rows / 288 KB) — flagged as the next retention target.

## Design

- `memory-retention.ts` — **pure, deterministic planner.** Two orthogonal bounds per (room, partition): age (`retentionDays`) and count (`maxRowsPerRoom`). A row is evicted iff *either* bound would evict it; the newest rows are always preserved. Deletion set is oldest-first and clamp-able (`maxDeletePerSweep`). **OFF by default** — no active bound yields an empty plan, so merging this changes no behavior until an operator opts in.
- `memory-retention-service.ts` — registered runtime `Service`. Resolves config from `getSetting` (host-folded) with a `process.env` fallback; schedules a sweep only when a bound is active (unref'd timers, re-entrancy guard, restart-safe with no persisted cursor). Batches deletes through the adapter's `deleteManyMemories`, which drops each memory's embeddings in the same transaction. Scope is the canonical memory partitions only — never `logs`, `central_messages`, or auth-audit tables.

## Config (all optional; absent ⇒ bound disabled)

29:Te53,## COLD-PATH LATENCY FIX (the real user stall)

Closes the two stacked stalls Shadow felt as 4-6s that the warm first-BYTE harness structurally could not see (REALPATH-LATENCY-2026-07-21, #16734). Two focused commits.

### A. Cold auth+scope hydration (request layer) — commit 1
Fresh-session shared-agent chat pays two serial cold Hyperdrive waves in `resolveSharedAgent`: API-key validation, then user/org hydration overlapped with the agent lookup (#16629 parallelized wave 2; wave 1 stays serial before it). Measured **1.09-4.43s** on the first cold hit.

**Fix:** short-TTL (30s) resolved-scope cache keyed by (api-key-hash-prefix, agentId). The second cold-session hit (or a composer-mount prewarm) skips BOTH DB waves. Follows the IAC safety model — positive entry only for a fully-authorized SHARED-tier agent (never the time-sensitive bootstrap window); a HIT still re-runs the revoke-invalidated key validation + org-match, so a revoked/expired/re-scoped key is never served stale. Miss → authoritative gate unchanged. 30s is 10x tighter than the validation cache's own 600s TTL already gating this path.

### B. Provider-retry backoff sleep (inference layer) — commit 2
The interactive Cerebras turn had NO cross-provider fallback (`withRateLimitFailFast` only handles 429), so a transient 5xx fell into the AI SDK's retry loop that **sleeps 2s→6s before retrying the same dead provider**. #16713 only bounded it.

**Fix:** `getInteractiveCerebrasLanguageModel` fails over to OpenRouter **instantly (no backoff)** on 402/429/5xx, and the shared-turn `maxRetries` default drops to **0** — the instant failover owns resilience. No-op without `OPENROUTER_API_KEY`; the default cerebras branch is unchanged (429 still surfaces for the graceful rate-limit reply).

### Harness
The measurement gap (first-byte on one warm reused conversation) is fixed out-of-repo in `/tmp/latency-harness.sh`: measures first-TOKEN + full-response, uses a FRESH auth session per cold probe (KEY_MINT_CMD), n≥5 cold, never cancels the stream after byte 1 so retry backoff is visible. Same thresholds (warm med<1.5/p95<2, cold p95<3), now measured honestly.

The **compaction / handoff-regeneration** side of sovereign memory. Siblings merged today:
- #16700 canonical file boot (read identity from files)
- #16702 canonical memory writeback (append per-fact daily memory with provenance)

Where writeback records *individual* facts as they happen, a **handoff** is the periodic *summary* the next session reads first. This PR adds the missing piece: a generator that turns a long session transcript into a **bounded** handoff and rotates it **atomically**.

### What it does
- **Preserves every seeded decision / todo / open-thread.** Extraction is deterministic (marker-based: `DECISION:`, `TODO:`/`- [ ]`, `OPEN THREAD:`, plus `[bracket]` variants), so nothing load-bearing is silently dropped by a flaky model call. Each item carries provenance (turn index + role + optional timestamp).
- **Stays bounded.** The handoff is what every future boot pays for, so it is size-capped (default 16 KiB). Preserved carry-forward items are **never** truncated; only the free-form recent-context tail is trimmed (oldest-first) to fit. If the preserved set alone exceeds the cap we surface it rather than lose state.
- **Rotates atomically.** Reuses #16702's `writeFileAtomic` (same-dir temp + rename). A crash between temp-write and rename leaves the **old or new complete** file, never a torn one.
- **File firewall.** All writes go through #16702's `authorizeWrite` — deny-by-default, confined to the approved write root, `HANDOFF.md` already allowlisted.
- **Idempotent-ish.** Re-compacting **replaces** rather than appends, so the handoff never grows unbounded even when the prior handoff is fed back in.

# Background

### The stall lives in the model call, not scope

Instrumented probe against api-staging (`273cf3199`), `Server-Timing` from `canonical-scoped-stream.ts`:

- On turns that short-circuit **before** inference (402 insufficient-credits), latency is **flat ~750ms, zero bimodality** (`scope`~185ms, `bridge`~530ms across 20/20 turns). Post-#16629 scope is no longer the stall.

### The smoking gun: default AI-SDK retry backoff on a no-fallback provider

The shared (Tier 0) turn calls `generateText`/`streamText` with **no `maxRetries`**, so it inherits the AI SDK v6 default: `maxRetries: 2`, `initialDelayInMs: 2000`, `backoffFactor: 2` (verified in `ai@6.0.174` `retry-with-exponential-backoff`). The shared default model is the Cerebras route, which has **no cross-provider fallback** — `withRateLimitFailFast` only short-circuits **429**; **5xx/network keep the SDK's retry**.

So a single transient Cerebras 5xx/network blip adds pure sleep before the turn can succeed or surface:
- 1 retry → **+2s** → observed ~5s stalled sub-band
- 2 retries → **+2s+4s = +6s** → observed ~7-9s stalled sub-band

That is an exact match for the measured bimodal quanta (fast ~1s floor; stalled clusters at ~4.5-5.1s and ~7.5-8.9s). The SDK also honors upstream `Retry-After` (capped 60s), which explains the clean ~5s stalls.

- Keeps **one fast heal attempt** for the common single transient blip.
- Caps worst-case added latency to a single ~2s backoff instead of ~6s.
- Lets a persistent upstream failure surface fast to the existing refund/degrade path (`error-policy:J2`) instead of hanging the interactive turn.

This is the smallest change that removes the stall without weakening the fail-closed billing/refund semantics or the 429 graceful-degrade behavior. It does not touch `withRateLimitFailFast`, the OpenRouter fallback, embeddings, or dedicated-container turns.
