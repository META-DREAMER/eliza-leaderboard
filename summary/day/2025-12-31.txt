14:T1c65,### Summary
Adds 3-legged "login + approve" Twitter/X auth (OAuth 2.0 Authorization Code + PKCE) to @elizaos/plugin-twitter without shipping any client secret, while keeping full backward compatibility with the existing env-var OAuth 1.0a credentials. Also adds a broker-ready auth mode stub (not functional yet) so a future Eliza-hosted broker can be added without touching tweet logic.

This requires a “Twitter broker” I referenced below which is a future Eliza-hosted service (not implemented in this repo) that would sit between the plugin and Twitter to handle the parts that require a client secret and a user session.

What it is
A separate web service (owned by ElizaOS) that:
- Runs the OAuth2 “login + approve” flow on behalf of users
- Stores the client secret and refresh tokens securely
- Hands the agent/plugin short‑lived access tokens (so the plugin never needs secrets)


### What changed in this PR (exact)
- Introduced a single auth abstraction: TwitterAuthProvider#getAccessToken(): Promise<string>
- Added TWITTER_AUTH_MODE (env|oauth|broker) and centralized auth selection
- env mode (default): preserves TWITTER_API_KEY / TWITTER_API_SECRET_KEY / TWITTER_ACCESS_TOKEN / TWITTER_ACCESS_TOKEN_SECRET behavior
- oauth mode: OAuth2 PKCE interactive login + token refresh + persistence
- broker mode: stub-only; fails clearly until an Eliza Twitter broker service exists
- Refactored TwitterAuth + client call sites to use provider-driven tokens (no direct env reads in request logic)
- Added unit tests for PKCE, OAuth2 refresh flows, token store, and broker stub
- Updated docs and plugin parameter metadata

### Auth modes
#### 1) Legacy env mode (no behavior change)
Set:
- TWITTER_AUTH_MODE=env (or omit)
- TWITTER_API_KEY
- TWITTER_API_SECRET_KEY
- TWITTER_ACCESS_TOKEN
- TWITTER_ACCESS_TOKEN_SECRET

#### 2) OAuth2 PKCE mode ("login + approve")
Set:
- TWITTER_AUTH_MODE=oauth
- TWITTER_CLIENT_ID
- TWITTER_REDIRECT_URI (loopback recommended, e.g. http://127.0.0.1:8080/callback)
Optional:
- TWITTER_SCOPES (default: tweet.read tweet.write users.read offline.access)

First run prints an authorization URL. After approval it stores tokens and auto-refreshes.

Requires a 

### Local callback server (required for best UX)
In oauth mode, the plugin starts a small local HTTP server bound to 127.0.0.1 to capture the OAuth redirect at the host/port/path in TWITTER_REDIRECT_URI.
- If it can’t bind, it falls back to "paste the redirected URL".

### Broker mode (stub; requires Eliza Twitter broker server)
If TWITTER_AUTH_MODE=broker:
- Requires TWITTER_BROKER_URL
- This PR does NOT implement the broker server; it only provides the plugin-side provider stub.
- Later, an Eliza-hosted broker (e.g. eliza twitter auth server) can hold the client secret and return short-lived access tokens.

### Validation
- bun run build
- bun run test:coverage (unit tests; E2E stays env-mode only / skipped without credentials)
