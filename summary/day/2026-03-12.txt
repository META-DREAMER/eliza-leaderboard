<!-- /CURSOR_SUMMARY -->15:T2344,## Summary

Adds a full Docker container + Headscale VPN infrastructure layer as an alternative sandbox provider for Milaidy agents. Instead of running agents in Vercel Sandboxes, operators can now deploy agents as Docker containers on remote VPS nodes with optional WireGuard mesh networking via Headscale.

**34 files changed, ~8,200 lines added**

---

## Motivation

Vercel Sandboxes are convenient but limiting: no persistent filesystem, no SSH access, no custom networking, constrained resources. For agents that need a real VPS-like environment (CLI tools, persistent data, inter-agent communication), we need Docker containers on dedicated infrastructure.

This PR introduces a provider abstraction so both backends coexist cleanly, controlled by a single env var.

---

## Architecture

```
                    MILAIDY_SANDBOX_PROVIDER=docker
                              │
User → Eliza Cloud API → SandboxProvider Factory
                              │
              ┌───────────────┼───────────────┐
              ▼                               ▼
     VercelSandboxProvider          DockerSandboxProvider
     (existing behavior)                      │
                                    ┌─────────┼─────────┐
                                    ▼         ▼         ▼
                               SSH Client  Node Mgr  Headscale
                                    │         │         │
                                    ▼         ▼         ▼
                              Hetzner VPS  Placement  VPN Mesh
                              (Docker)     Strategy   (WireGuard)
```

## What's included

### 1. Sandbox Provider Abstraction (`lib/services/sandbox-provider.ts`)

Extracted a `SandboxProvider` interface from the existing Vercel-specific code:

```typescript
interface SandboxProvider {
  create(config: SandboxCreateConfig): Promise<SandboxHandle>;
  stop(sandboxId: string): Promise<void>;
  checkHealth(healthUrl: string): Promise<boolean>;
  runCommand?(sandboxId: string, cmd: string): Promise<string>;
}
```

Factory function reads `MILAIDY_SANDBOX_PROVIDER` env var (`vercel` | `docker`), defaults to `vercel`. Existing Vercel code extracted into `VercelSandboxProvider` with zero behavior changes.

### 2. Docker SSH Client (`lib/services/docker-ssh.ts`)

SSH client with connection pooling for managing containers on remote nodes:
- Connection pool with configurable max connections
- Command execution with timeout support
- Container lifecycle (create, stop, remove, inspect, logs)
- Image management (pull, check)

### 3. Docker Sandbox Provider (`lib/services/docker-sandbox-provider.ts`)

Full `SandboxProvider` implementation for Docker:
- Container creation on remote nodes via SSH
- Port allocation: bridge (18790-19790), web UI (20000-25000)
- Health check polling with configurable timeout
- In-memory container registry with DB backing
- Optional Headscale VPN integration (graceful degradation if not configured)
- Metadata passthrough (node_id, container_name, ports, VPN IP, image)

### 4. Node Manager (`lib/services/docker-node-manager.ts`)

Multi-node management with smart placement:
- Least-loaded allocation strategy
- Periodic health checks
- Capacity tracking and reporting
- Node enable/disable for maintenance

### 5. Headscale VPN Layer

**Client** (`lib/services/headscale-client.ts`):
- Full REST API client for Headscale control plane
- Node management, pre-auth key generation, route handling, health checks

**Integration** (`lib/services/headscale-integration.ts`):
- Container VPN lifecycle: prepare → register → cleanup
- Ephemeral pre-auth keys per container
- VPN registration polling (60s timeout)
- Automatic node cleanup on container stop

### 6. Database Schema (`db/migrations/0034_docker_nodes.sql`)

New `docker_nodes` table:
```sql
CREATE TABLE docker_nodes (

  node_id TEXT UNIQUE NOT NULL,
  hostname TEXT NOT NULL,
  ssh_port INTEGER DEFAULT 22,
  capacity INTEGER DEFAULT 8,

  status TEXT DEFAULT 'unknown',
  allocated_count INTEGER DEFAULT 0,
  last_health_check TIMESTAMPTZ,
  ssh_user TEXT DEFAULT 'root',

```

## Provisioning flow (Docker)

```
1. Database setup     → Neon DB provisioned (same as Vercel path)
2. VPN preparation    → Generate Headscale pre-auth key (optional)
3. Container creation → SSH to least-loaded node, pull image, run container
4. VPN registration   → Wait for container to join mesh (60s timeout)
5. Health check       → Poll /health endpoint via provider
6. State restore      → Push backup via bridge API (if exists)
7. Persist metadata   → Store docker fields in milaidy_sandboxes
8. Return handle      → bridgeUrl + healthUrl (VPN IP or node hostname)
```

## Configuration

### Required for Docker provider
```env
MILAIDY_SANDBOX_PROVIDER=docker
MILAIDY_DOCKER_NODES=node1:192.168.1.100:8,node2:192.168.1.101:8
MILAIDY_SSH_KEY_PATH=/path/to/ssh/key
MILAIDY_SSH_USER=root
```

### Optional (Headscale VPN)
```env
HEADSCALE_API_KEY=hskey-api-xxx
HEADSCALE_API_URL=http://headscale:8081
HEADSCALE_USER=milaidy
```

### Switching providers
```env
# Use Vercel (default, no change needed)
MILAIDY_SANDBOX_PROVIDER=vercel

# Use Docker
MILAIDY_SANDBOX_PROVIDER=docker
```
