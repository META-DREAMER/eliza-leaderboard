14:T7eb,There are three different states of interacting with public agents. They have fundamentally different user intents and should have a distinct UI.

## State 1: Unauthenticated Visitor (Not Signed In)

**User Intent:** "I clicked a link on Twitter, I'm curious, let me try this agent"

**What they should see:**

* Clean chat interface focused on the agent
* Agent avatar, name, @username, and brief bio/description
* **No** Private/Public toggle
* **No** Edit button
* **No** Fork button (yet—they need to sign up first)
* Copy shareable link button to share with others

**Interaction model:**

* Allow **2-3 free messages** before soft gate
* After limit: "Sign up to continue chatting" overlay

## State 2: Authenticated Non-Owner (Signed In, Not Creator of Agent)

**User Intent:** "I want to chat with this agent OR I want to make my own version"

**What they should see:**

* Chat interface
* Agent info + creator attribution
* **"Chat"** and **"Fork"** buttons (NOT Edit)
* **No** Private/Public toggle
* Clear indication this isn't their agent
* Copy shareable link button to share with others

## State 3: Owner (Signed In, Is Creator)

**User Intent:** "I want to manage/edit my agent"

**What they should see:**

* Full control UI
* **Chat** and **Edit** tabs
* **Private/Public toggle** with clear state indicator
* Share button (when public)
* Analytics/stats (future: views, chats, forks)<br><br>
