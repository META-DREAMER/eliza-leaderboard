## Summary

This PR refactors the Ollama plugin integration to make it truly conditional based on configuration, rather than being always included as a universal fallback. This change improves the flexibility of model selection and ensures Ollama is only loaded when explicitly configured or when no other LLM providers are available.

## Problem

Previously, the Ollama plugin was:

- Always included in the project-starter character configuration as a "universal fallback"
- Automatically set up during project creation regardless of user selection
- Hardcoded as a fallback even when users had configured other LLM providers

This caused issues where:

- Ollama would be unnecessarily loaded even when cloud-based LLMs were configured
- The plugin registration order could interfere with intended model precedence
- Users couldn't opt out of Ollama if they only wanted to use cloud providers

## Solution

### 1. **Conditional Ollama Loading in Character Configuration**

- Changed `packages/project-starter/src/character.ts` to only include the Ollama plugin when `OLLAMA_API_ENDPOINT` is configured
- Maintains proper plugin order: Core → LLM providers → Ollama (if configured) → Platform plugins → Bootstrap

### 2. **Removed Automatic Ollama Setup in CLI**

- Removed forced Ollama configuration from `packages/cli/src/commands/create/actions/creators.ts`
- No longer automatically sets up Ollama as a universal fallback during project creation

### 3. **Improved Model Selection Logic**

- Added `hasEmbeddingSupport()` helper function in `packages/cli/src/commands/create/utils/selection.ts`
- Identifies which AI models have built-in embedding support (local/Ollama, OpenAI, Google)
- Replaced hardcoded checks for `claude` and `openrouter` with the new helper function

### 4. **Consistent 'local' Model Mapping**

- Changed model mapping so 'local' consistently maps to the Ollama plugin
- Improved clarity in setup flow where 'local' means Ollama for both AI and embeddings

### 5. **Simplified Setup Flow**

- Removed redundant Ollama setup code from `setupAIModelConfig()`
- Consolidated embedding configuration logic
- Only installs Ollama plugin when explicitly selected or needed for embeddings

## Impact

- **Better Performance**: Ollama plugin only loads when needed, reducing unnecessary overhead
- **Clearer Intent**: Users explicitly choose when to use Ollama rather than having it forced
- **Improved Flexibility**: Easier to use cloud-only setups without local model fallbacks
- **Consistent Behavior**: All LLM provider plugins now follow the same conditional loading pattern
