### 🧠 Use Case

A user starts a conversation with the blockchain agent. At some point, they ask a question the blockchain agent can’t answer, but the support agent can.

I want the blockchain agent to **pass the question internally to the support agent**, get the response, and send it back to the user — seamlessly.

### 🧪 What I’ve Tried

Previously, Eliza supported an endpoint where I could send a message to a specific agent via `agentId` and get a response. That endpoint seems to no longer exist.

Here’s what I tried instead:

1.  Created a server and added both agents to it.
2.  Created a channel in that server and added both agents to the channel.
3.  Used the endpoint:
    `/api/messaging/central-channels/:channelId/messages`
    to forward the message.

### ⚠️ Issue

-   The support agent takes time to respond.
-   To check the response, I use:
    `/api/messaging/central-channels/:channelId/messages`
    But this requires polling, which isn’t reliable — sometimes the agent never responds or the polling misses it.
