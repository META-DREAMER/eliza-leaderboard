14:Ta4c,## Description

Running `elizaos create <project-name>` fails at the build step on macOS with:

```
$ bun run build.ts
Error: Bun's postinstall script was not run.

This occurs when using --ignore-scripts during installation, or when using a
package manager like pnpm that does not run postinstall scripts by default.

To fix this, run the postinstall script manually:
  cd node_modules/bun && node install.js

Or reinstall bun without the --ignore-scripts flag.
error: script "build" exited with code 1
```

The CLI then cleans up the project directory and exits, leaving nothing behind.

## Root Cause

`@elizaos/cli` and `@elizaos/plugin-bootstrap` both list `"bun": "^1.3.4"` as a **runtime dependency**. When a new project installs these packages, the `bun` npm package becomes a transitive dependency.

The `bun` npm package has a `postinstall` script (`node install.js`) that:
1. Looks for `node_modules/@oven/bun-darwin-aarch64/bin/bun` (on Apple Silicon)
2. Copies it to `node_modules/bun/bin/bun.exe`

However, **bun the package manager intentionally skips extracting its own 60MB binary** from `@oven/bun-darwin-aarch64` into node_modules (it's already installed system-wide). This leaves `node_modules/@oven/bun-darwin-aarch64/bin/` empty.

When `install.js` runs, it can't find the binary and exits silently. `node_modules/bun/bin/` is left with Windows `.exe` stubs. When `bun run build.ts` executes, bun detects the stubs and throws the error above.

## Steps to Reproduce

1. Install bun via `curl -fsSL https://bun.sh/install | bash`
2. Install elizaos CLI: `bun install -g @elizaos/cli`
3. Run: `elizaos create my-first-agent`
4. Follow prompts (any database/model choice)
5. Observe failure at build step

## Environment

- macOS (Apple Silicon / darwin-aarch64)
- bun 1.3.11
- @elizaos/cli 1.7.2

## Fix

The `bun` npm package should be removed from the runtime dependencies of `@elizaos/cli` and `@elizaos/plugin-bootstrap`. It is only needed as a devDependency for types (`@types/bun`). The bun runtime is already available system-wide when users install elizaos via bun.

```diff
# In @elizaos/cli and @elizaos/plugin-bootstrap package.json:
- "dependencies": {
-   "bun": "^1.3.4",
+ "devDependencies": {
+   "@types/bun": "^1.x.x",
```

## Workaround

Until fixed, users can create projects manually:

```bash
cp -r ~/.bun/install/global/node_modules/@elizaos/cli/templates/project-starter ~/my-first-agent
cd ~/my-first-agent
bun install
cp ~/.bun/bin/bun node_modules/@oven/bun-darwin-aarch64/bin/bun
chmod +x node_modules/@oven/bun-darwin-aarch64/bin/bun
node node_modules/bun/install.js
bun run build.ts
